## SEO 与移动端优化（不改任何文字，只动结构和样式）

- **移动端完整响应式**：补 viewport meta、解除 `body{min-width:1200px}`、
  导航改汉堡菜单+侧边抽屉、右侧客服栏在手机上改底部固定条。
  抽屉用 `transform` 移出屏幕而非 `display:none`，10 个导航链接始终在 DOM 里
- **窄屏版式修复**（`gen-mobile-css.py` 自动生成，433 条覆盖规则）：
  原站是纯 PC 版式，固定像素宽高、浮动分栏、按 1200px 版心算的绝对定位坐标、
  按 1920px 稿写的 vw 字号，在手机上会撑破视口、把正文挤成窄条、
  用 `overflow:hidden` 把正文裁掉，甚至把元素推出容器导致宽度算成 0（正文不渲染）。
  生成器解析 19 个样式表 + 197 个页面的页内 `<style>` + 内联宽度，按模式反推覆盖：
  放开写死的宽高、解开裁切与 line-clamp、分栏改单列、负偏移拉回容器、vw 换算成 px。
  分两档生效：`<=1199px` 只做防溢出（保留多栏），`<=768px` 完整降级。**1200px 以上一像素未动。**
  14 套页面模板逐一实测：横向溢出 0、被裁正文 0、零宽文字 0、过小字号 0
- **性能**：首屏外图片全部 `loading="lazy"`，全站图片补 `width`/`height` 消除 CLS
- **h1 归位**：原站把 h1 用在了站点 logo 上，231 个页面没有主题 h1。
  改为 logo 降级为 div、CMS 标记的 `id="h1_rep_title"` 元素升级为 h1，
  有主题 h1 的页面从 69 页增加到 248 页（只换标签名，文字一字未改）
- **语义地标**：`div.topWrap` → `<header>`，`div.footWrap` → `<footer>`
- **清理原站残留**：删掉原站主的百度/搜狗/神马站长验证码、解开「关于/联系」页上的
  nofollow、2551 个死链加 nofollow、JSON-LD 类型由 SoftwareApplication 改为 Product
  并修正 710 个 404 的 URL、删掉百度统计/CNZZ/百度推送/在线客服插件/手机端跳转脚本/
  友情链接/llms.txt 死链/模板变量残留
- **新增** `sitemap.xml`（按实际页面生成）

改动前后用 `seo-snapshot.py` 做过机器校验：title / 链接 / alt / description **零变化**。
窄屏版式修复只改了 `assets/brand.css` 一个文件，299 个页面的 HTML 与上一版**逐字节一致**

## GEO（面向 AI 答案引擎）

目标不是搜索结果里的一条蓝链，而是被豆包/Kimi/百度AI/ChatGPT 抽取、写进答案、署上来源。

- **robots.txt 已全面放开**，并逐个列出 22 家爬虫（豆包 Bytespider、百度、神马、
  OAI-SearchBot、PerplexityBot、ClaudeBot、Google-Extended…）—— 部分爬虫只读自家 UA 段
- **新增 `llms.txt` / `llms-full.txt`**：一页说清「这个站是什么 + 有哪些内容」，
  按产品/资讯/栏目分组，链接与描述全部来自各页面本身
- **sitemap 升级**：lastmod 用文章真实发布日期（不再是构建时间戳），
  按页面类型分 priority 与 changefreq，加了 image sitemap 扩展
- **canonical + og 补回**，首页两个 URL（`/` 与 `/808bc58e7137.html`）统一指向站点根
- **删掉负资产**：202 处伪造的「5星/1条评价」（Google 明令禁止的 spammy structured data）、
  236 处非法的 `"price":"面议"`、SoftwareApplication 模板残留字段、8 处伪造 Review
- **从现有 HTML 推导出的新标记**（零文字改动）：

  298 条面包屑 → `BreadcrumbList`；64 篇资讯 → `Article` + 真实发布日期 + `<time datetime>`；
  40 个列表页 → `ItemList`；频道页 `Service` → `CollectionPage`；首页 → `WebSite` + 完整 `Organization`

  `cnc-faq.html` 常见问题（FAQPage）、`cnc-materials.html` 材料选型对照表、
  `cnc-tolerance.html` 公差与工艺能力、`cnc-glossary.html` 术语表（30 条 DefinedTerm）

作者字段的处理：原站把「作者：」写成了 `cnc加工厂家`、`铝合金车铣cnc加工厂家www.伟创业.com`

## 清除原站埋的隐藏文字

抓取来源在正文里塞了大量 `style="color:#FFFFFF"` 的元素，内容是「产品关键词 + 栏目名」，
白字白底肉眼看不见，里面还带内链。这是 Google 明令禁止的 Hidden text and links，
百度同样打击 —— 而站点已全面放开抓取，留着会拖累前面所有 SEO/GEO 工作。

判定不能按「是不是白字」一刀切：实测有一部分白字落在深色背景图上（亮度 0.29）是正常可见的设计。
`_hidden-text-audit.html` 逐页渲染，向上解析每个白字元素的真实底色
（背景图画进 canvas 采样平均亮度），只有落在亮度 > 0.75 的浅底上才判为隐藏。

判定必须同时满足两个条件，**缺一不可**：
1. 元素的**计算颜色**接近白色。只匹配 style 属性里的 `color:#FFFFFF` 字样是不够的 ——
   原站很多 style 属性被 CMS 弄坏了（`font-family` 的引号没闭合，把后面的声明一起吞掉），
   属性里有白色字样但根本没生效，那些文字是可见的。全站 2717 个带白色字样的元素里，
   **1722 个属于这种，计算颜色并不是白色**。
2. 它落在的**实际底色**是浅色（亮度 > 0.75）。底色解析要跳过 10x10 的 `no-repeat` 项目符号
   —— 那是装饰不是底色。

结果：**隐藏 580、不是白字 1722、无文字 409、深色底上可见 2、判不了 4**。
`remove-hidden-text.py` 删除 546 个元素，另有 31 个隐藏的 `h1` **改为去掉白色让它显形**
（那是页面唯一的主题标题，删了这 31 页就没有 h1 了）。

核对：
- `title` / `description` / `alt` **零变化**，标题数**零减少**，只少了 11 个隐藏的关键词链接
- 标签配对零错误，没有破坏 HTML 结构
- 没有 h1 的页面数保持 51 不变
- 复核：全站重新扫描，残留隐藏文字 **0**
