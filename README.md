## PC 端的一处堆叠（本轮修复）

SEO 那轮给全站图片补 `width`/`height` 属性消除 CLS 时留了个副作用：
当 CSS 只设了宽度、没设高度，`height` 属性会作为表现性提示生效，
把图片撑成属性里的原始高度而不是按比例缩放。

`.jx li img` 就是受害者 —— CSS 写 `width:224px`，`height` 属性是 379，
图片被撑到 379px 高（应为 224px），把固定 583px 高的工程师卡片撑破，
简介文字压到下一节标题上。

修法是一条不带 `!important`、只用 `img` 标签选择器的规则：

    img { height: auto; }

优先级（0,0,1）高于 `height` 属性的表现性提示，低于任何带 class 的 CSS 高度声明，
所以按固定高度裁剪的图片（如 `.news1-c dt img{height:381px}`）不受影响。

和未改造的原始抓取备份逐项对比过：改动前当前版比原始版多 1 处堆叠，修复后两者
在 1440px 下的真实堆叠数都是 **0**（原先检出的 4 处经核实全是被 `overflow:hidden`
裁掉的轮播克隆节点，属检测误报，自检工具已排除这类）。

## 卡片参差、平板浮动外溢、看不见的文字

这一轮是**第一次有意改动桌面版式**（前几轮一直保持桌面像素不动）——
因为下面几条是原站自带的设计缺陷，不是抓取或改造带来的。

### 桌面（>=1200px）

| 症状 | 根因 | 改法 |
|---|---|---|
| 产品卡片同排高差 74px | 配图比例不统一：`1024x1024` 与 `600x450` 混用，float 网格不会自动等高 | 图框定死 `aspect-ratio:4/3` + `object-fit:contain`（留白，不裁产品本身） |
| 案例卡片高差 71px | 同上，另有几张缺图的占位 | 同上；定比例后缺图也能占住位置 |
| 「推荐产品」标题条参差 | `.cx-xgcp-3pl-01-list h4` 只写了 `line-height:35px`，没有高度上限 —— 原设计假设标题只有一行，实际 20 字的标题会折成两行 | 定死两行高 70px，超两行收省略号（`title` 属性仍是全文）。注意这一排是 SuperSlide 轮播，卡片的 `float`/`width` 是 JS 写在内联样式里的，**不能改成 flex** |
| `.pro2` 卡片标题读不清 | `#666` 灰字绝对定位直接压在照片上，没有衬底 | 加白色半透明衬底 |
| 翻页计数「1/3」看不见 | 白字，原站没给它任何底色，对比度实测 **1.00** | 加深色小牌子 |

### 平板（769~1199px）

这一档最麻烦：版式还是桌面那套多栏，但版心被压窄了。

- **浮动外溢**：`.g-super` 这类 section 原本靠 `height:989px` 兜住浮动子元素。
  窄屏必须放开这个死高度，一放开父级就塌成 0 高，`.super-c dl` 里 777x538 的大图
  直接漏进下一节 ——把「案例」标题的**行盒从 1009px 挤到 192px**，
  14 个字被迫折成 4 行，再连环压到下面的行业导航上。
  给这些浮动容器补 `display:flow-root`（只兜住浮动，不像 `overflow:hidden` 会裁切）。

- **文字裁切不再在平板档放开**。生成层原本会把 `overflow:hidden` / `nowrap` /
  `-webkit-line-clamp` 统统解开（怕手机端裁字），但平板档还是桌面版式：
  省略号和定高是这套版式自洽的一部分，解开之后标题换行变高，
  底下那些按固定偏移摆好的简介、日期、按钮全被压住。
  **解一半更糟** —— 只解 `overflow` 不解 `nowrap`，标题不换行直接横着溢出，
  压到隔壁卡片的标题和右侧日期上（1024px 实测 4 处叠字）。
  现在放开只保留在 <=768px 单列档。搜索引擎按手机视口渲染，落在这一档，
  正文照样能被完整读到。

- 另外四处：案例图框按 `466:313` 定比例；产品详情「在线咨询」按钮不换行
  （盒子只有 98px 宽、左边还有 58px 图标位，一换行第二行正好压在电话号码上）；
  资讯标题宽度让开右侧的绝对定位日期；工艺流程说明留够两行位。

### 检测工具本身的两类假阳性

排查中发现「元素堆叠」的判定一直在虚报，两处都修了：

1. **浮动下方的块盒**。浮动只挤压行盒、不挤压块盒，所以「块盒压着浮动」
   在任何浮动布局里都成立，但文字其实是错开的。改成只量元素**自己那几行字**的
   行盒（对每个直接文本节点建 `Range` 取 `getClientRects()`）。
2. **被裁掉的文字**。`.p14-product-2-desc` 只有 177px 宽、`overflow:hidden`，
   里面是 `nowrap` 的一长串字，行盒量出来有 1565px —— 看不见的那 1388px
   会跟隔壁卡片"相交"。改成行盒先按祖先（含元素自身）的 `overflow` 裁一刀再比。

工具侧还做了：自检页支持 `?w=` 换视口宽度；新增 `_regress-check.html`
把当前版本和 `原型/原始网页_备份/`（改造前的原始抓取）逐页跑同一套检测，
只报**两者的差集**，用来区分「我改出来的回归」和「原站本来就有的毛病」。

**缓存这个坑踩了两次**：iframe 会用缓存的 `brand.css`，改了样式跑出来还是旧结果。
而且**追加一份新样式表是不够的** —— 追加只能覆盖同名规则，
被删掉的规则仍留在缓存那份里继续生效。必须直接改掉原 `link` 的 `href`。

## 清除原站埋的隐藏文字

抓取来源在正文里塞了大量 `style="color:#FFFFFF"` 的元素，内容是「产品关键词 + 栏目名」，
白字白底肉眼看不见，里面还带内链。这是 Google 明令禁止的 Hidden text and links，
百度同样打击 —— 而站点已全面放开抓取，留着会拖累前面所有 SEO/GEO 工作。

判定不能按「是不是白字」一刀切：实测有一部分白字落在深色背景图上（亮度 0.29）是正常可见的设计。
`_hidden-text-audit.html` 逐页渲染，向上解析每个白字元素的真实底色
（背景图画进 canvas 采样平均亮度），只有落在亮度 > 0.75 的浅底上才判为隐藏。

判定必须同时满足两个条件，**缺一不可**：
1. 元素的**计算颜色**接近白色。只匹配 style 属性里的 `color:#FFFFFF` 字样是不够的 ——
   原站很多 style 属性被 CMS 弄坏了（`font-family` 的引号没闭合，把后面的声明一起吞掉），
   属性里有白色字样但根本没生效，那些文字是可见的。全站 2717 个带白色字样的元素里，
   **1722 个属于这种，计算颜色并不是白色**。
2. 它落在的**实际底色**是浅色（亮度 > 0.75）。底色解析要跳过 10x10 的 `no-repeat` 项目符号
   —— 那是装饰不是底色。

结果：**隐藏 580、不是白字 1722、无文字 409、深色底上可见 2、判不了 4**。
`remove-hidden-text.py` 删除 546 个元素，另有 31 个隐藏的 `h1` **改为去掉白色让它显形**
（那是页面唯一的主题标题，删了这 31 页就没有 h1 了）。

核对：
- `title` / `description` / `alt` **零变化**，标题数**零减少**，只少了 11 个隐藏的关键词链接
- 标签配对零错误，没有破坏 HTML 结构
- 没有 h1 的页面数保持 51 不变
- 复核：全站重新扫描，残留隐藏文字 **0**
